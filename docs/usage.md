# 本地使用指南

> 仅原创合成演示，禁止用于生产设备写入。推荐、模型、知识、设备与质量结果均不代表生产系统。本文不会保证任何工况一定产生推荐或改善。

架构、三节点 Agent 图、七工具与字段语义见 [architecture.md](architecture.md)。以下命令面向已经安装本项目及其依赖的 Python 3.12 本地环境；不包含联网安装、模型下载或生产数据导入。

## 1. 从新目录启动

### 1.1 选择独立、尚不存在的数据目录

在工程根目录执行命令。以下只将新数据目录放在现有项目目录之外，便于避免将数据库、凭据和模型误提交。

```bash
DATA="$HOME/parameter-recommendation-demo-new"
.venv/bin/parameter-recommendation init "$DATA"
```

`DATA` 是本地数据目录路径，不是 token。父目录必须已存在；目标目录必须**尚不存在**，不应指向其他工程数据，不接受符号链接或 `..` 穿越。若名称已用过，另选新名称，不要为重跑演示删除原数据。

`init` 会：

- 创建受限权限的本地目录、SQLite 数据库和制品目录。
- 创建 `local-admin` 与 `synthetic-plant` 授权。
- 导入短射、飞边、翘曲、正常、缺失输入、OOD 六个原创上下文；各有独立合成设备。
- **仅显示一次访问 token**。妥善保存在你控制的安全位置，不放入源码、截图、聊天、URL、shell 命令参数或环境变量。服务端只存其 hash。

初始化**不会训练 BC、调用工具提供方、创建推荐、批准或执行设备**。不要将初始化成功当作推理或效果验证成功。

### 1.2 实际训练并注册 BC

```bash
.venv/bin/parameter-recommendation train "$DATA"
```

出现 `Bearer token (hidden)` 时在隐藏提示中输入上一步 token。不要把 token 拼到命令中。当前训练命令需要该工厂的 admin/reviewer 权限。

命令真正生成合成专家示范并训练 NumPy MLP，作独立分组校准和留出评测，然后注册本人该工厂的当前模型。输出中需要区分：

| 输出 | 应如何阅读 |
| --- | --- |
| `model_id`, `model_hash`, `model_version` | 当前模型对象、内容来源和整数对象版本 |
| `model_artifact` | 模型 JSON 制品 hash |
| `metrics_artifact` | 独立 `{model_hash, metrics}` 评测制品 hash，不是权重 |
| `metrics.training` | 实际初始/最终损失、训练记录，不是预写“训练通过” |
| `metrics.split`, `metrics.calibration` | 训练/校准/测试血缘与校准结果 |
| `metrics.test` | 合成留出集的组合准确率、增量误差、覆盖率与对照；不是现场效果 |

数值以本次实际输出为准，本文不预设合格阈值或改善率。模型和评测保存在数据目录，不要手工编辑制品。重复 `train` 会更新当前模型对象版本，使此前创建的任务/推荐来源失效；开始任务后不要为解决某个拒绝结果而反复换模型。

### 1.3 显式选择 TEST 工具提供方并启动

```bash
.venv/bin/parameter-recommendation serve "$DATA" --test-mode
```

浏览器打开：

```text
http://127.0.0.1:8005
```

默认端口为 **8005**。需要其他空闲端口时使用 `--port`，例如：

```bash
.venv/bin/parameter-recommendation serve "$DATA" --test-mode --port 8006
```

请用 `127.0.0.1`，不要改为公网地址或依赖 `localhost` 的 Host 行为。启动消息的 `inference_checked: false` 表示启动本身没有验证推理；页面可打开也不表示 BC 已训练。

`--test-mode` 的 `SyntheticProvider` 是明确标识的确定性协议演练器，**不是语言模型**，不代表真实 LLM 推理验收。它只安排受控工具调用；BC 推理、约束、授权、数据库和合成设备仍走真实后端实现，不会被 TEST 跳过。

CLI 也支持 `--model-url` 或 `--runtime-config` 的显式本地提供方，但三者必须恰选一个，不能与 `--test-mode` 混用。本指南不创建运行时配置，不下载模型，也不承诺未单独验证的真实模型效果。服务不会在本地模型失败后偷偷切换 TEST 或云端。

## 2. 连接工作台并核对来源

1. 在“连接与身份”的密码框中输入 token，点击**连接工作台**。
2. 核对显示的用户、角色、工厂、ACL 版本及提供方指纹；TEST 模式应明确可辨识。
3. 在“1 · 工艺上下文”选择一个上下文，先核对设备、材料、模具、工艺版本、时间、测量与样本资格。
4. 阅读四参数的精确字符串和单位，不把增量当百分比。
5. 查看右侧“行为克隆 BC · 来源与评测”。模型必须属于本人当前工厂；没有模型时先回终端训练，页面不会自动训练。

token 只在本页面内存使用；密码框在提交后清空，不写浏览器持久存储或 Cookie。刷新页面、离开页面或“退出并清空”后需要重新登录。401/403 会清空会话，权限发生变化后应重新鉴权，而不是重复旧操作。

模型面板展示来源摘要与绑定评测，不展示权重。若评测缺失会明确说明，不应把未显示的测试指标理解成通过。

## 3. 创建和运行推荐任务

### 3.1 创建不等于运行

选中上下文后点击**创建推荐任务（不运行）**。此时任务为 `created`，模型尚未开始选择工具。核对任务的 context/source_snapshot 后，再点击**显式运行 / 恢复任务**。

运行时工具提供方逐轮从可用菜单选择动作。七工具为：

`get_process_context`、`retrieve_experience`、`predict_bc`、`draft_recommendation`、`check_constraints`、`request_human_input`、`submit_recommendation`。

它们运行在实际 `agent -> guard -> tools` 三节点循环中；工具顺序受先决条件约束，审核与设备操作不在图内。等待当前运行请求返回服务端真实停止/最终状态，不反复点击运行。

### 3.2 理解正常停止结果

| 状态 | 含义与下一步 |
| --- | --- |
| `submitted` | 产生 `pending_review` 推荐；转到独立审核，不代表已经批准 |
| `awaiting_input` | 需要人工补缺；按下一节处理 |
| `no_recommendation` | BC 拒绝或没有安全可执行候选；查看 prediction/issues，不造参数继续 |
| `blocked` | 查看 error、用量、来源和租约；先核查，不能假定可安全重试 |
| `cancelled` | 任务已取消；不应再提交后续工具，但已知调用用量仍保留 |

正常、OOD、过期、低置信度、缺失或硬约束不合格都可能不产生推荐。“没有推荐”不是必须修掉的 UI 错误，更不能用未审核模型解释作为执行依据。

在“服务端签发证据”中查看过程、经验、BC 和约束结果；“签发”表示后端生成记录，哈希不是密码学签名。在“权威候选”表中核对绑定原值、原始 Δ、量化 Δ、目标、方向与实际单位。经验只能辅助说明，不豁免硬约束。

### 3.3 人工补缺

当任务为 `awaiting_input` 时，才会显示“人工补充缺失上下文”表单。只能填写服务端要求且原先为空的：

- `material_viscosity`：合成无量纲黏度，0.3–2.5。
- `ambient_c`：环境温度，5–45 degC。

填写真实的**演示输入依据**及必填说明，不把示例值说成生产测量。点击**补充并生成新上下文版本（不运行）**。后端将更新 revision、清空旧派生证据/候选；不会刷新原观测时间或重置预算。再次核对来源后，需要单独点击运行。

不能在此修改既有值、四个设定参数、owner、role、工艺版本或模型；页面也没有通用参数编辑器。

### 3.4 取消、恢复和重载

- **取消任务**可在运行请求尚未返回时独立发送。服务端阻止后续工具生效，但可能仍需记录已经发出的模型调用用量；取消不是远程进程立即停止的承诺。
- **重载服务端状态**重新读取授权范围的对象；它中断旧浏览器请求，但**不等于取消服务端任务**。
- 下拉“打开 / 恢复已有任务”或任务列表“打开 / 恢复”只选择并展示记录，不自动运行。恢复按钮是否可用还取决于服务端状态、租约、来源与预算。
- 任务 `submitted/no_recommendation/cancelled` 是终态；不通过取消已提交任务来撤销审核或设备动作。

当前预算上限为 14 模型调用、12 工具、32000 tokens、420 秒累计执行耗时，租约为 900 秒；这些不是可以由页面修改的额度。后端用 `accounted_call_elapsed_s` 记录已并入任务的调用耗时水位，只把新补记的调用耗时加到 `elapsed_s`，避免恢复读取重复加算同一笔消耗；运行计时也不能把累计值调低。页面不提供水位编辑，刷新、补缺、取消或对账均不重置预算。取消后仍可能补记实际调用成本，遗留调用的处理见第 6 节。

## 4. 独立审核推荐

在“3 · 已提交推荐 · 独立人工审核”选择所需 `pending_review` 推荐，核对：

1. 推荐 ID、状态、版本和当前完整 `content_hash`。
2. 绑定 context/model/constraint 来源及全部 Evidence。
3. 四参数权威候选与硬约束资格。
4. “未审核的模型解释 · 非权威文本”只能作为解释，不得覆盖参数或提供执行事实。

这里的**“独立人工审核”指与 Agent 提交、执行请求分别进行的一次显式、已授权的人工动作，不要求由不同的人完成，也不是双人复核（four-eyes）制度**。本人作为 owner，且当前具有该工厂 reviewer/admin 权限时，可以审核自己的推荐；默认初始化账号 local-admin 可在自己的演示对象上完成此步骤。

owner + 当前授权 plant 隔离仍然生效：其他用户即使是 reviewer/admin，也不能审核该 owner 的对象；operator 不能因“同一人可审核”而获得审核权限。当前工程没有另一个审核员接管他人对象的协作分派流程。

审核决定没有默认值，必须主动选择**批准（仍不执行）**或**拒绝**，填写审核依据，再点击**提交人工审核决定**。页面/API 说明文字上限为 2000 字符。拒绝后该推荐不能直接改为批准或执行；若要重新分析，应明确建立新任务，而非修改旧审批记录。

### 两个不同的精确哈希

| 阶段 | 必须绑定的值 |
| --- | --- |
| 审核 | `pending_review` 推荐当时的完整 Store `content_hash` |
| 请求执行 | 审核记录加入 payload 后，`approved` 推荐新的完整 Store `content_hash` |

`candidate_hash` 不能替代 recommendation_hash，审核前的 hash 也不能拿来请求执行。页面自动使用当前选中对象 hash；换对象或 hash 改变时会重置确认表单，须重新核对。API 使用者应重新读取当前对象，不猜测 hash。

## 5. 分步请求、应用、回读与成熟观察

### 5.1 请求合成执行：还没有应用

选择已批准推荐，在“① 创建执行请求”核对来源与参数，勾选合成确认，点击**请求合成执行（不应用）**。

后端再次检查推荐来源、上下文时效、硬约束、设备 active context 与原值，冻结设备 version/revision。成功后 recommendation 为 `execution_pending`，execution 为 `pending`。**设备参数此时尚未改变**。

HTTP 的 `confirmed` 必须是真正的 JSON `true`，`1`、`1.0` 或字符串不算显式确认。

### 5.2 应用到合成设备：还没有回读确认

在“② 选择执行记录”确认对应 execution，在“③ 应用到合成设备”重新勾选确认，点击**应用到合成设备（NOT production）**。

仅 `pending` 可应用。后端复核来源、设备原值和冻结版本后实际更新本地设备并保存回执；独立 ACK 成功后显示 `applied`。`applied` **不是** `executed`，不能跳过回读。

“应用”不是打印一份成功消息，也不是调用生产设备。若请求中断、返回错误或界面提示状态未确认：

1. 不立即重新应用，不制造新执行请求绕过未知状态。
2. 点击**重载服务端状态**，重新选择执行记录。
3. `applied` 或 `unknown` 应进入独立回读；`unknown` 的应用按钮被禁用。

通用幂等回执绑定 action_id、阶段、目标与正文；同一键换内容会拒绝。页面不把请求超时当作“未发送”，也不自动重试设备应用。

### 5.3 独立回读：实际存储事实核验

点击**读取设备回执并核验**。它读取真正保存的 `device_receipt` 和本地设备当前值，核验请求、目标、原值、来源、身份、hash 与版本。

- 匹配时 execution 与 recommendation 均为 `executed`，显示 `readback.current`、回读 hash 与时间。
- 无回执、回执损坏、参数/版本/active context 不匹配时仍为 `unknown`，不能人工输入“已成功”解除。
- 表格“已核验回读值”为空时，页面不会拿目标值冒充回读值。

unknown 后重新发送应用不被允许；管理员的模型调用用量对账也不能解决设备 unknown。

### 5.4 等待至少 60 秒，再请求观察

从**有效回读时间**起真实经过至少 60 秒，点击**请求成熟合成观察**。创建请求后等待或应用前等待不能计入。页面按钮在 `executed` 时即可点击，但成熟性由服务端判断，不靠浏览器倒计时保证。

若过早点击得到 `observation_immature`，没有生成改善结论；待满时间后先重载状态，再请求观察。不修改时钟、种子或样本数来绕过条件。

当前 HTTP/UI 使用服务端默认每组 120 个新样本，固定默认种子，后组使用不同种子；没有 seed/样本选择控件。内部服务允许的样本范围为严格整数 60–10000，不是 UI 开放选项。

成功后推荐为 `observed`，execution 仍保留 `executed`。查看：

- before/after 各自的缺陷数（分子）、样本数（分母）、缺陷率和 95% 区间。
- `difference_after_minus_before` 为后减前，负值表示样本缺陷率下降。
- `difference_ci95` 是独立二项采样差值区间：区间全负才是合成改善，全正为变差，其余为无明确改善。
- `synthetic_observed_improvement`、`no_clear_improvement`、`worsened` 均来自实际计算，不预设结论。

**before 不是已观测生产基线。** 两组都是同一冻结上下文、不同参数下独立生成的合成采样；“配对”指上下文配对，不是实际产品前后测量。`causal_effect_proven` 和 `baseline_is_observed_production` 都为 false。已完成观察不能通过换 action_id/seed 反复刷取有利结果。

## 6. 管理员：未知模型调用用量对账

此处只处理模型调用账本，不处理设备回执。admin 仍只能处理本人、当前授权工厂内的任务，不能借对账接管其他 owner 的对象。

当任务为 `running`、`blocked` 或 `cancelled`，且 `unknown_calls > 0`、登录角色为 admin 时，界面显示“未知模型调用用量对账”表单。遗留 `running` 任务也可点击“显式运行 / 恢复任务”请求后端检查；浏览器不根据本地时钟判断租约是否失效，仍有效时后端返回 busy。先核查任务 error、unknown_calls、租约及可验证的本地调用记录；显示按钮不等于允许重试，也不自动发起调用。

- `call_id` 必须来自真实任务调用记录，不能凭空填写。当前 UI 有输入框，但不提供完整 `calls` 账本明细列表；若页面没有显示具体 call_id，需要本地维护者按 task/owner 核查已有账本，而不是猜测 ID。
- 可核实的 tokens 填 0–100000 范围内的整数，不能小于已保存的已知用量；**仍未知就留空**，空值不是 0。只有确认未发送或确有依据时才填 0。
- 填写核查依据，勾选“没有可使用的结果，不虚构回复或设备事实”，再点击**提交无结果用量对账**。
- 工作租约仍有效时拒绝对账。对账不自动再次运行，保留已经确定的消耗；用量仍未知会保守占用剩余 token 预算，因而任务可能耗尽预算。
- 该操作不解除托管进程清理未知锁，不生成模型回复、不产生推荐，也不能让合成设备变为 executed。

任务摘要的 `tokens` 只是已知/已对账累计值，必须同时看 `unknown_calls`（包括 `started` 与 `unknown`）。**tokens 已知不代表结果已确定**：提供方结果或清理状态不明确时，可靠用量仍要入账，但该调用仍为 unknown，不能据此自动重试或继续工具。可靠的已知用量即使遇到无效回复、取消或撤权也会记账。

### 已取消任务与迟到回复

服务/API 和页面均允许对 `cancelled` 任务的遗留调用显式对账：租约过期或不存在后，`started` 记录可转为 `unknown/interrupted_call`，再由该任务 owner 的 admin 通过页面表单或 `POST /api/tasks/{task_id}/reconcile`，按真实 call_id、无可用结果声明及用量依据对账。不修改数据库状态、不冒用他人身份，也不通过对账恢复已取消任务。

对账清除待处理动作，但已取消任务仍保持 `cancelled`，不会恢复运行。调用记为 `failed/reconciled_no_result` 后，即使原工作者迟到返回，也只能按较大值补记该调用的 tokens 和耗时，不能调低成本、恢复为可用回复或使工具动作重新生效。其他任务即使对账后回到 `created`，也需重新核对来源与剩余预算，再显式运行；对账不是免费重试。

## 7. 审计、只读查看与常见拒绝

“5 · 本人授权范围审计”展示本人当前工厂可见的最近记录，最多 100 条，使用“重载服务端状态”刷新。它不是无限历史导出，也不包含 token。展开详情可核对操作、对象、来源 hash、版本与合成说明。

| 情况 | 正确处理 |
| --- | --- |
| `init_exists` | 换一个尚不存在的新目录，或对既有目录直接使用 train/serve；不要覆盖原数据 |
| 没有 BC 模型 | 本地 CLI 显式训练注册；现有任务绑定旧来源时创建新任务，不期待自动换模型 |
| 没有推荐 / BC abstain | 查看缺失、OOD、置信度、时间和硬约束 issues；不手工编写参数强行推进 |
| `source_changed` / hash 或版本不一致 | 重载并核对当前来源；旧任务或推荐不能无声改绑最新模型/上下文 |
| `context_expired` | 补缺不会刷新时间；当前页面没有新上下文导入器。演示需要新合成输入时按受控导入流程或新独立演示目录处理，不改数据库时间 |
| `device_conflict` / 设备原值或版本改变 | 停止执行旧候选，核对 active context；禁止复位设备以让旧请求通过 |
| `busy` / `provider_busy` | 已有运行或有效租约，等待真实状态；重载不是强制接管 |
| `model_unknown` / provider cleanup unknown | 不自动重试；走有依据的调用核查/本地维护流程 |
| execution `unknown` | 禁止再次应用，使用实际设备回执回读；无法核验就保持未知 |
| `observation_immature` | 从有效回读起等满 60 秒，重载后再请求；未成熟不认定改善 |
| 401/403 | 页面清空身份；重新登录并确认授权，不复用旧 Principal |
| `idempotency_conflict` | 同 action_id 的目标、阶段或正文变了；先查已存结果，不改键盲目重复执行 |
| 列表没有他人对象 | owner/plant 隔离的正常结果，管理员角色不提供跨 owner 自动接管 |
